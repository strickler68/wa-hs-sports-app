1. **Reorganized the project into a structured directory**, `wa-hs-sports/`,
   mirroring a typical GIS project layout:
   ```
   wa-hs-sports/
   ├── sql/            schema.sql, seed_data.sql, db_roles_and_grants.sql
   ├── data/           schools_seed.csv, enrich_and_load.py

   ├── supabase/migrations/   Supabase-ready copies of the 3 SQL files
   └── DEPLOY.md       step-by-step hosting instructions
   ```
   This is a real git repo now (`git init` + initial commit done), ready
   to push to GitHub whenever you create one.

2. **Got the backend actually running** (first time — previously only
   config files existed, nothing had ever been executed):
   - Installed PostgreSQL 16 + PostGIS in this session's sandbox
   - **Found and fixed a real bug**: `schema.sql`'s `schools` table
     declared the `city` column twice, which silently aborted the whole
     script every time it was run. Fixed in both `sql/schema.sql` and
     `supabase/migrations/..._schema.sql`.
   - Loaded schema + seed data + roles into a live `wahsports` database —
     confirmed 10 league rows, 72 schools, 72 league memberships
   - Installed PostgREST, pointed it at the live database, confirmed
     `GET http://localhost:3000/schools` returns real JSON for all 72
     schools, and `GET /leagues` / `GET /games` both work correctly
   - **Caveat**: this database and API only exist inside this Claude Code
     session's container. They disappear when the session ends. This was
     a working proof that the architecture is real, not a persistent
     deployment.

3. **Chose a low-cost public hosting plan** (budget: ~$10-15/mo
   acceptable, domain wanted):
   - **Supabase** (free tier) for the database + API — it runs PostgREST
     internally, so this is the same architecture already built, just
     hosted for free instead of self-run
   - **Cloudflare Pages** (free) for the two static HTML frontends
   - **Cloudflare Registrar** (~$10-12/year) for the domain — the only
     real recurring cost, roughly **$1/month amortized**
   - Ruled out Render/Neon (free tier cold-starts after 15 min idle — bad
     for a live-scores app) and self-hosting on personal hardware (zero
     cost but you own uptime risk)
   - Substack came up as a *content/newsletter* idea, not a hosting
     option — orthogonal to all of the above, worth revisiting for the
     "distribute written recaps" side of the project later

4. **Prepped everything deployable** so the account-creation steps (which
   only you can do — they need your own login/payment) are a straight
   copy-paste:
   - `supabase/migrations/` — the schema/seed files as-is, plus a
     **Supabase-adapted** roles file. Important adaptation: Supabase
     already owns a role literally named `authenticator` internally, so
     the original `CREATE ROLE authenticator ...` would have failed on
     import. The adapted version grants the same permissions to
     Supabase's built-in `anon`/`authenticated` roles instead. (The
     original `sql/db_roles_and_grants.sql` is untouched — still correct
     for a self-hosted, non-Supabase PostgREST setup.)
   - `public/` — Cloudflare Pages deploy root, with a tiny device-split
     landing page that sends phones to `/mobile/` and everything else to
     `/desktop/`
   - `DEPLOY.md` — the exact click-by-click steps for: buying the domain,
     creating the Supabase project and running the 3 migrations in order,
     pushing to GitHub, connecting Cloudflare Pages, attaching the domain
